About

I fix the structure,
not the symptom.

Over 4 years as a game server and backend developer, I've built hands-on experience that spans far beyond maintenance and new features, covering performance optimization, operational infrastructure, and real-time server design. Directly responsible for live services running across Korea, Japan, Taiwan, and English-speaking regions, I've tracked down and resolved issues that cut straight to the heart of stability and performance: eliminating login bottlenecks, migrating ranking systems to Redis, building a chat server from the ground up, stabilizing payments, and executing DB migrations.

Years of incident response and structural refactoring have reinforced one conviction: patching surface symptoms is a temporary fix, but understanding the root cause and redesigning the structure is what actually lasts. Backend work happens entirely out of sight, but the quieter the server, the more freely users stay immersed, and the more the operations team can focus on building rather than firefighting. I find meaning in that invisible work, where silence is the only sign that anything was done at all.

Case study / CocoMine

Bottlenecks that grew
with concurrency,
solved in the structure.

Problem
Locks on every login API forced all users' requests into a single line, so waits grew whenever traffic spiked.
Fix
Reduced contention around the request-wide locks and split independent work to run in parallel. Also expanded the DB connection pool and added missing indexes.
Result
Login dropped from 30 s to 3 min down to 10–30 s, and ranking queries from 10–20 s to 1–2 s after moving to Redis.
  1. LOGINLess lock contention
  2. SESSIONConcurrent requests split
  3. CHANNEL POOLLeast-loaded, auto scale-out
  4. REDISRanking cache
  5. MYSQLPersistent data, indexes

I designed and reworked every stage, from login to the database.
